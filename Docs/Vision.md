## ۱. مقدمه

### ۱.۱ هدف سند
این سند چشم‌انداز، دامنه و ذی‌نفعان پروژهٔ **ورکینو** را تعریف می‌کند.
هدف آن ایجاد یک درک مشترک میان تیم توسعه، مشتری و ذی‌نفعان درباره
«چه چیزی می‌سازیم، برای چه کسی، و چرا» است.

این سند **قرارداد رسمی** نیست، بلکه **مرجع راهنما** برای تصمیم‌گیری‌های
بعدی در طول چرخهٔ حیات پروژه است و در هر Sprint بازبینی می‌شود.

## ۲. چشم‌انداز محصول

### ۲.۱ بیانیهٔ چشم‌انداز (Vision Statement)
افرادی که از **منطقه‌ای به منطقه‌ای دیگر یا از شهری به شهر** دیگر نقل مکان می‌کنند، ممکن است برای پیدا کردن **افراد حرفه‌ای و متخصص** در محل جدید با فهرست بلندی از افراد مواجه شوند و انتخاب فرد مناسب برایشان دشوار باشد. این محصول با دسته‌بندی افراد بر اساس **سابقه کاری، مهارت‌ها و حوزه تخصصی**، به کاربران کمک می‌کند تا متخصصان موردنیاز خود را راحت‌تر پیدا کنند، سوابق آن‌ها را بررسی کنند و برای دریافت خدمات یا همکاری در پروژه‌های مختلف با آن‌ها ارتباط برقرار کنند.


### ۲.۲ ارزش پیشنهادی (Value Proposition)

| برای | ارزش |
|------|-------|
| **مشتری نهایی** | بهره‌مندی از افراد متخصص |
| **صاحب محصول (ادمین)** | ایجاد فرصت های شغلی، برقراری ارتباط |
| **افراد دارای کسب‌ و کار** | پیدا کردن افراد متخصص برای پروژه های خصوصی و عمومی |

### ۲.۳ مزیت رقابتی
- تنوع: دارا بودن متخصص در بیشتر حوزه ها
- تمرکز: ارائه خدمات با بالاترین کیفیت
- اعتماد: گارانتی و اصالت محصول تضمین‌شده
- محلی‌بودن: پشتیبانی از تمامی مناطق کشور حتی شهر های کوچک

## ۳. مشکل و فرصت

### ۳.۱ مشکل فعلی (Problem Statement)
صاحبان فروشگاه‌های کوچک لوازم خانگی با چالش‌های زیر روبه‌رو هستند:
1. **محدودیت جغرافیایی:** فقط مشتریان محلی از آن‌ها خرید می‌کنند.
2. **نبود کانال آنلاین:** نمی‌توانند محصولات خود را آنلاین عرضه کنند.
3. **فرآیند دستی سفارش:** سفارش‌ها تلفنی، یادداشت‌شده و پرخطا.
4. **عدم شفافیت موجودی:** مشتری نمی‌داند چه چیزی موجود است.
5. **نبود امکان مقایسه:** مشتری نمی‌تواند محصولات را کنار هم ببیند.

### ۳.۲ فرصت (Opportunity)
- رشد خرید آنلاین لوازم خانگی در ایران
- افزایش نفوذ اینترنت در شهرهای کوچک
- عدم حضور فروشگاه‌های کوچک در فضای آنلاین
- امکان ایجاد یک بازار نیچ (Niche) برای محصولات اصل با گارانتی

## ۵. محدودهٔ محصول

### ۵.۱ داخل محدوده (In Scope — MVP)

**کاربری (Functional):**
- **F-01** نمایش کاتالوگ محصولات با تصویر، قیمت و مشخصات
- **F-02** جست‌وجو و فیلتر پیشرفته (برند، قیمت، مصرف انرژی، ظرفیت)
- **F-03** صفحهٔ جزئیات محصول با گارانتی و مشخصات فنی
- **F-04** مقایسهٔ ۲-۳ محصول در جدول
- **F-05** سبد خرید (افزودن، حذف، تغییر تعداد)
- **F-06** ثبت سفارش با فرم و اعتبارسنجی
- **F-07** پنل ادمین: افزودن/ویرایش/حذف محصول
- **F-08** پنل ادمین: مشاهدهٔ سفارش‌ها و تغییر وضعیت

**غیرکاربری (Non-functional):**
- **NF-01** زمان بارگذاری صفحه < ۲ ثانیه
- **NF-02** پشتیبانی از ۱۰۰ کاربر همزمان
- **NF-03** رابط کاربری واکنش‌گرا (Responsive) برای موبایل و دسکتاپ
- **NF-04** رمزنگاری گذرواژه‌ها (bcrypt)
- **NF-05** پشتیبانی از زبان فارسی و RTL

### ۵.۲ خارج از محدوده (Out of Scope)

| مورد | دلیل |
|------|-------|
| پرداخت واقعی (درگاه بانکی) | نیاز به مجوز و زیرساخت — فقط شبیه‌سازی |
| اپلیکیشن موبایل | تمرکز روی وب |
| سیستم حمل و نقل | خارج از توان یک ترم |
| گارانتی واقعی و خدمات پس از فروش | پیچیدگی حقوقی |
| چت پشتیبانی آنلاین | اولویت پایین |
| چند زبانه (فارسی/انگلیسی) | تمرکز روی فارسی |

### ۵.۳ محدودیت‌ها (Constraints)
- **زمانی:** ۱۴ هفته، ۳ Sprint
- **تیمی:** ۳-۴ نفر
- **فنی:** بدون سرور اختصاصی، استقرار روی سرویس ابری رایگان
- **بودجه:** صفر (فقط ابزارهای رایگان)

## ۸. رویکرد و متدولوژی

### ۸.۱ متدولوژی
- **Scrum سبک‌شده:** ۳ Sprint دو-سه هفته‌ای
- **ابزار مدیریت:** GitHub Projects
- **جلسات:** Sprint Planning، Daily (کوتاه، آنلاین)، Review، Retrospective

### ۸.۲ فناوری پیشنهادی
| لایه | فناوری |
|------|--------|
| Backend | Node.js + Express |
| Frontend | React |
| Database | PostgreSQL |
| Version Control | Git + GitHub |
| CI/CD | GitHub Actions |
| مستندسازی | Markdown در GitHub |

### ۸.۳ Definition of Done
یک Story وقتی «تمام» است که:
1. کد نوشته و Merge شده باشد.
2. تست Unit برای آن نوشته شده باشد.
3. Code Review شده باشد.
4. مستندات مربوطه به‌روز شده باشد.
5. در محیط Demo کار کند.
