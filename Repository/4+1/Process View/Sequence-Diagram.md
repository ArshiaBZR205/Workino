# Sequence Diagram — ورکینو

## ۱. مقدمه

این دیاگرام ترتیب تعاملات بین کاربران و اجزای سیستم را در سناریوهای اصلی پروژه ورکینو نشان می‌دهد.

## ۲. سناریو: ثبت درخواست خدمات

### ۲.۱ Actors
- **مشتری** — ثبت‌کننده درخواست
- **Frontend** — رابط کاربری
- **Backend** — پردازش درخواست‌ها
- **Database** — پایگاه داده

### ۲.۲ ترتیب

1. مشتری روی «ثبت درخواست» کلیک می‌کند.
2. Frontend درخواست POST به `/api/requests` می‌فرستد.
3. Backend اطلاعات درخواست را اعتبارسنجی می‌کند.
4. Backend اطلاعات درخواست را در Database ذخیره می‌کند.
5. Backend درخواست‌های مرتبط را برای متخصصان مشخص می‌کند.
6. Backend اعلان درخواست جدید را برای متخصصان مرتبط ثبت می‌کند.
7. Backend شناسه درخواست را برمی‌گرداند.
8. Frontend پیام موفقیت نمایش می‌دهد.

## ۳. سناریو: مشاهده متخصصان

### ۳.۱ Actors
- **مشتری**
- **Frontend**
- **Backend**
- **Database**

### ۳.۲ ترتیب

1. مشتری وارد صفحه متخصصان می‌شود.
2. Frontend درخواست GET به `/api/specialists` می‌فرستد.
3. Backend فهرست متخصصان را از Database دریافت می‌کند.
4. Backend فهرست متخصصان را برمی‌گرداند.
5. Frontend فهرست متخصصان را نمایش می‌دهد.

## ۴. سناریو: ارسال پیشنهاد قیمت

### ۴.۱ Actors
- **متخصص**
- **Frontend**
- **Backend**
- **Database**

### ۴.۲ ترتیب

1. متخصص وارد حساب کاربری خود می‌شود.
2. متخصص درخواست‌های مرتبط با تخصص خود را مشاهده می‌کند.
3. متخصص یک درخواست را انتخاب می‌کند.
4. متخصص قیمت پیشنهادی و توضیحات خود را وارد می‌کند.
5. Frontend درخواست POST به `/api/quotes` می‌فرستد.
6. Backend اطلاعات پیشنهاد را اعتبارسنجی می‌کند.
7. Backend پیشنهاد قیمت را در Database ذخیره می‌کند.
8. Backend پیام موفقیت را برمی‌گرداند.
9. Frontend پیام موفقیت را نمایش می‌دهد.

## ۵. سناریو: انتخاب پیشنهاد قیمت

### ۵.۱ Actors
- **مشتری**
- **Frontend**
- **Backend**
- **Database**

### ۵.۲ ترتیب

1. مشتری پیشنهادهای قیمت درخواست خود را مشاهده می‌کند.
2. مشتری یکی از پیشنهادها را انتخاب می‌کند.
3. Frontend درخواست مربوط به انتخاب پیشنهاد را به Backend ارسال می‌کند.
4. Backend وضعیت پیشنهاد انتخاب‌شده را بررسی می‌کند.
5. Backend وضعیت پیشنهاد انتخاب‌شده را به accepted تغییر می‌دهد.
6. Backend وضعیت سایر پیشنهادها را به rejected تغییر می‌دهد.
7. Backend وضعیت درخواست را به in_progress تغییر می‌دهد.
8. Backend نتیجه را برمی‌گرداند.
9. Frontend پیام موفقیت را نمایش می‌دهد.

## ۶. خطاهای ممکن

| خطا | کد | راهکار |
|---|---|---|
| اطلاعات نامعتبر است | 400 | نمایش پیام خطا |
| کاربر وارد نشده است | 401 | هدایت به صفحه ورود |
| اطلاعات پیدا نشد | 404 | نمایش پیام خطا |
| دسترسی غیرمجاز | 403 | نمایش پیام عدم دسترسی |
| خطای سرور | 500 | نمایش پیام خطا |
